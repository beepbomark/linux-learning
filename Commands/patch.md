# Linux `patch` Command

The `patch` command applies changes from a **diff/patch file** to an existing file or directory.

It is commonly used to:
- Apply changes generated by `diff`
- Update source code
- Apply bug fixes
- Reverse previously applied changes
- Test whether a patch can be applied safely

---

## Key Points

- Patch files are commonly created with `diff -u`
- `patch` reads the instructions inside the patch file
- `-pN` controls how many directory levels are removed from file paths
- `--dry-run` tests a patch without modifying files
- `-R` reverse a patch
- Always review or test a patch before applying it

---

## 1. Basic Workflow

Create a patch:
```bash
diff -u old.txt new.txt > changes.patch
```

Apply the patch:
```bash
patch old.txt < changes.patch
```

---

## 2. Basic Syntax

```bash
patch [OPTION] [FILE] < PATCH_FILE
```

Example:
```bash
patch file.txt < changes.patch
```

Can also use:
```bash
patch < changes.patch
```

If the patch file contains the target filename, `patch` can usually determine which file to modify.

---

## 3. Creating a Patch

Suppose:
`old.txt`
```
apple
banana
orange
```
`new.txt`
```
apple
grape
orange
```

Create the patch:
```bash
diff -u old.txt new.txt > changes.patch
```

`changes.patch` may contain:
```Diff
--- old.txt
+++ new.txt
@@ -1,3 +1,3 @@
 apple
-banana
+grape
 orange
```

---

## 4. Apply a Patch

```bash
patch old.txt < changes.patch
```

After applying:
```
apple
grape
orange
```

---

## 5. Dry Run

Before applying a patch, test it with:
```bash
patch --dry-run < changes.patch
```

This checks whether the patch can be applied without modifying anything.

This is a good habit before applying unfamiliar patches.

---

## 6. Reverse a Patch

Use:
```bash
patch -R < changes.patch
```

This reverses the changes.

Example:
```
grape
```
can be changed back to:
```
banana
```
using the same patch file with `-R`.

---

## 7. Patch Directory Paths

Patch files often contain paths such as:
```
a/src/file.txt
b/src/file.txt
```

May need:
```bash
patch -p1 < changes.patch
```
The `-p` option removes directory levels from paths.

---

## 8. Understanding `-p`

Suppose the patch refers to:
```
a/src/config.txt
```

`-p0`
```bash
patch -p0 < changes.patch
```
Keeps the full path:
```
a/src/config.txt
```

`-p1`
```bash
patch -p1 < changes.patch
```

Removes the first directory:
```
src/config.txt
```

`-p2`
```bash
patch -p2 < changes.patch
```

Removes:
```
a/src/
```
leaving:
```
config.txt
```

---

### `-p` Quick Reference

|Option|Original Path|Result|
|---|---|---|
|`-p0`|`a/src/file.txt`|`a/src/file.txt`|
|`-p1`|`a/src/file.txt`|`src/file.txt`|
|`-p2`|`a/src/file.txt`|`file.txt`|

---

## 10. Apply Patch to a Directory

Change into the project directory:
```bash
cd project/
```

Then:
```bash
patch -p1 < ../changes.patch
```

Or specify a directory:
```bash
patch -d project -p1 < changes.patch
```

---

## 11. Create Backup Files

Use:
```bash
patch -b < changes.patch
```

This creates a backup of the original file before modifying it.

May see files such as:
```
file.txt.orig
```

---

## 12. Patch Rejection

If part of the patch cannot be applied, `patch` may create a reject file:
```
file.txt.rej
```
This contains the changes that could not be applied.

May also see:
```
file.txt.orig
```
which may contain the original file.

---

## 13. Why a Patch May Fail

A patch may fail because:
- The file has already changed
- The patch was already applied
- The wrong directory is being used
- The wrong `-p` value is used
- The expected lines no longer exist
- The patch was created against a different version

Test with:
```bash
patch --dry-run -p1 < changes.patch
```

---

## 14. Useful Options

|Option|Meaning|
|---|---|
|`pN`|Remove N directory levels from paths|
|`-R`|Reverse the patch|
|`-b`|Create backup files|
|`-d DIR`|Change to directory before applying|
|`--dry-run`|Test without modifying files|
|`-s`|Silent / less output|
|`-N`|Ignore patches that appear already applied|

---

## 15. Recommended Workflow

```bash
diff -u old.text new.txt > changes.patch

# then inspect
cat changes.patch

# test
patch --dry-run < changes.patch

# apply
patch < changes.patch

# if necessary, reverse
patch -R < changes.patch
```
