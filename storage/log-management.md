# Log Management

## Log Basics

Logs are records generated by the operating system, services, applications, and security mechanisms. They provide visibility into system activity and are often the first place to investigate when troubleshooting issues.

Common uses:
- Troubleshooting service failures
- Monitoring system health
- Investigating security incidents
- Auditing user activity
- Diagnosing performance problems

Common log types:
|Type|Purpose|
|---|---|
|System Logs|Operating system events|
|Service Logs|Service startup, shutdown, and errors|
|Application Logs|Application-specific activity|
|Security Logs|Authentication and authorization events|
|Audit Logs|User and system activity tracking|

---

## Common Log Locations

Most Linux logs are stored under `/var/log`.

Common log files:
|Log file|Purpose|
|---|---|
|`/var/log/syslog`|General system messages (Debian/Ubuntu)|
|`/var/log/messages`|General system messages (RHEL/CentOS)|
|`/var/log/auth.log`|Authentication events|
|`/var/log/secure`|Authentication events (RHEL/CentOS)|
|`/var/log/kern.log`|Kernel messages|
|`/var/log/dmesg`|Boot-time kernel messages|
|`/var/log/boot.log`|Boot events|
|`/var/log/audit/audit.log`|Audit subsystem logs|

View log directory:
```bash
ls -lh /var/log
```

## Searching Logs

Search for specific keywords:
```bash
grep "error" /var/log/syslog
```

Case-insensitive search:
```bash
grep -i "failed" /var/log/auth.log
```

Count matching entries:
```bash
grep -c "sshd" /var/log/auth.log
```

Search recursively:
```bash
grep -R "database" /var/log
```

---

## Filtering Logs

Displaying only matching lines:
```bash
grep "ERROR" application.log
```

Exclude matching lines:
```bash
grep -v "INFO" application.log
```

Show recent failures:
```bash
grep "Failed password" /var/log/auth.log
```

Filter by date:
```bash
grep "May 20" /var/log/syslog
```

Combine filters:
```bash
grep "sshd" /var/log/auth.log | grep "Failed"
```

## Journalctl Basics

Modern Linux distributions using systemd store logs in the system journal.

View all journal entries:
```bash
journalctl
```

View recent entries:
```bash
journalctl -n 50
```

Follow logs in real time:
```bash
journalctl -f
```

View logs for a service:
```bash
journalctl -u ssh
```

View logs since boot:
```bash
journalctl -b
```

View today's logs:
```bash
journalctl --since today
```

View logs within a time range:
```bash
journalctl --since "2025-01-01 10:00:00" --until "2025-01-01 12:00:00"
```

## Log Rotation

Log rotation prevents logs from consuming excessive disk space.

Linux commonly uses `logrotate`.

Configuration files:
```
/etc/logrotate.conf
/etc/logrotate.d/
```

Check configuration:
```bash
cat /etc/logrotate.conf
```

Run manually:
```bash
sudo logrotate -f /etc/logrotate.conf
```

Common rotation actions:
- Rotate daily, weekly, or monthly
- Compress old logs
- Remove outdated logs
- Create new log files

## Log Archiving

Archiving preserves historical logs for auditing and troubleshooting.

```bash
tar -cvf logs.tar /var/log          # archive logs
tar -czvf logs.tar.gz /var/log      # archive and compress
tar -tvf logs.tar.gz                # list archive contents
tar -xzvf logs.tar.gz               # extract archived logs
```

Common use cases:
- Incident investigations
- Compliance requirements
- Long-term retention
- Backup operations

---

## Log Compression

Compression reduces storage requirements.

```bash
gzip application.log                # compress with gzip
gunzip application.log.gz           # decompress
zcat application.log.gz             # view compressed logs without extraction
zgrep "ERROR" application.log.gz    # search compressed logs
```

Compressed log examples:
```bash
syslog.1.gz
messages.2.gz
```
